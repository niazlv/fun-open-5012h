# Эмулятор FNIRSI-5012H

Исполняет немодифицированный `open-5012h.bin` на эмулируемом Cortex-M4
(Unicorn Engine, ядро QEMU) и моделирует остальную плату. Исходники прошивки
про эмулятор не знают — граница проходит по регистрам периферии и выводам
корпуса. Ассемблер прошивки (`uqsub8`/`sel` в поиске триггера, `ldm`/`stm` в
децимации), FPU-код, запись во flash через FMC и бит-бэнг дисплея исполняются
без замен.

Смещения и маски регистров берутся из `../include/gd32f4xx.h` — того же
заголовка, против которого собрана прошивка. `src/cmsis_shim/` подменяет
только `core_cm4.h` (квалификаторы `__IO` и т.п.), второго описания
кристалла в проекте нет.

## Что смоделировано

| Блок | Объём модели |
| --- | --- |
| Ядро | Cortex-M4: Thumb-2, DSP, FPU (Unicorn) |
| NVIC | вход/выход из прерываний по ARMv7-M B1.5 — Unicorn их не делает |
| RCU / PMU | биты готовности PLL/HXTAL/high-drive, которые опрашивает `sys_init()` |
| FMC | стирание секторов, запись слов с NOR-семантикой (`&=`), задержки busy |
| CRC | CRC-32/MPEG-2 по словам, как в аппаратном блоке |
| GPIO | OCTL/ISTAT/BOP/BC/TG; на выводах — шина LCD, реле, AC/DC, кнопки |
| TIMER1 | свободный счётчик 1 МГц (вся система таймаутов прошивки) |
| TIMER0/7 | период запросов DMA = частота выборки |
| DMA1 ch2 | двойная буферизация, CH2CNT в реальном времени, FTF-прерывание |
| AD9288 | чередование каналов, бит-реверс канала A, рассогласование пар |
| ST7789 | защёлкивание по фронту WR при CS=0, окна CASET/RASET, wrap |
| DAC / ADC0 | смещение по вертикали; батарея через RDATA |
| Кнопки | два приоритетных шифратора, как на плате |

Известные отступления от железа:

- модель DMA не переезжает границу буфера, пока прошивка не обработала FTF —
  иначе переполнение кольца зависело бы от скорости хоста (`dma_sync`,
  `src/board.c`);
- время = счёт инструкций, 1 инструкция = 1 такт @ 250 МГц, шаг 256
  инструкций (~1 мкс); тайминги TIMER1 и CH2CNT согласованы с этим временем;
- порядок половин AD9288 взят таким, каким его ожидает прошивка (чётный
  байт — ранний отсчёт); на железе он зависит от разводки data align, см.
  комментарий в `../capture.c`;
- коэффициенты мкВ/код по диапазонам взяты из заводских калибровок в
  `../config.c` — схемы с номиналами делителя нет. Эмулируемый прибор
  получается откалиброванным; всё после выданного АЦП байта прошивка
  считает сама.

## Сборка

```sh
brew install unicorn sdl2                      # macOS
sudo apt install libunicorn-dev libsdl2-dev    # Debian/Ubuntu

make -C ../make    # прошивка (arm-none-eabi-gcc)
make               # эмулятор
```

Без SDL2 собирается headless-вариант: окна нет, скрипты и PNG работают.

### Свой Unicorn

На Apple silicon страница JIT бывает либо записываемой, либо исполняемой, и
Unicorn переключает одно на другое дважды на каждый блок трансляции — на
профиле это треть всего времени эмулятора. Поэтому `make` собирает свой
Unicorn, с [патчем](unicorn/no-per-block-jit-toggle.patch), который лишнее
переключение убирает: **1.22x**, при побитово тех же скриншотах.

Просить об этом не нужно, но знать стоит: первая сборка качает исходники
Unicorn и занимает пару минут. Дальше библиотека уже лежит, и `make` её не
трогает — как и `make clean`. Убирает её `make distclean`.

| | |
| --- | --- |
| `make` | свой Unicorn там, где патч что-то даёт (Darwin/arm64); системный в остальных случаях |
| `make UNICORN=local` | свой в любом случае |
| `make UNICORN=system` | системный, ничего не собирать |

Патч ничего не меняет в том, что эмулируется, так что различить сборки можно
только по скорости. На Linux и Intel он бессмысленен — там переключения нет и
без него, поэтому `make` туда и не лезет.

## Запуск

```sh
make run
./build/fun5012h-emu ../make/build/open-5012h.bin --signal "sine f=1k vpp=1"
```

## Сигнал

```text
--signal "<форма> [ключ=значение ...]"
```

Суффиксы значений: `1k`, `2.5M`, `500m`, `20n`.

Формы: `dc sine square triangle saw pulse noise rc am burst uart glitch`.

| Ключ | Применимо к | |
| --- | --- | --- |
| `f=` | всем | частота |
| `vpp=` / `amp=` / `ofs=` | всем | размах / амплитуда / смещение |
| `duty=` | square, pulse, rc | скважность (`30` или `0.3`) |
| `rise=` | square, pulse, uart, glitch | фронт источника |
| `noise=` | всем | шум источника, СКЗ |
| `phase=` | всем | 0…1 |
| `baud= data= bytes= idle=` | uart | скорость, первый байт, байт в пачке, пауза в битах |
| `text=` | uart | payload как есть (ASCII/UTF-8, до 64 байт); съедает остаток спеки — ставить последним |
| `every= width=` | glitch | период выброса (в периодах), ширина |
| `modf= depth=` | am | модуляция |
| `cycles= period=` | burst | пачка |

```sh
--signal "square f=10k vpp=2 duty=30 rise=20n noise=10m"
--signal "uart baud=115200 data=0x48 bytes=4 vpp=3.3"
--signal "glitch f=200k vpp=2 every=32 width=80n"
```

UART: декодер прошивки требует паузу ≥ длины кадра между сообщениями, иначе
классифицирует поток как raw (`../uart_decode.c`). Генератор держит
`idle=` ≥ 12 бит.

## Тракт и АЦП

```text
--afe "[ideal|real] [ключ=значение ...]"
```

Дефолты — типовые значения из даташита AD9288 и полоса прибора. `ideal`
выключает всё.

| Ключ | Дефолт | |
| --- | --- | --- |
| `bw=` | `100M` | полоса −3 дБ; фронт на АЦП: `√(t_ист² + (0.35/bw)²)` |
| `overshoot=` | `4` | выброс/звон после фронта, % |
| `jitter=` | `2p` | апертурный джиттер, СКЗ |
| `dnl=` | `0.35` | нелинейность кодов, LSB; фиксированная на код → спуры, не шум |
| `adcnoise=` | `0.35` | шумовая полка, LSB |
| `ilgain=` / `iloffset=` | `0.8` / `5` | рассогласование половин AD9288, % / LSB |
| `probe=` | `1` | делитель щупа 1 или 10 |

Усилитель насыщается на ~40 LSB за краем окна АЦП: перегруженный сигнал
становится плоским, а не просто уходит за экран.

## Сценарии

```sh
./scripts/screenshots.sh    # перегенерировать все скриншоты README
```

```text
press <кнопка>[+<кнопка>]   нажать (60 мс, с учётом дебаунса)
hold / release <кнопка>
wait <мс>                   эмулируемое время
shot <png>
signal <спец>
echo <текст>
```

Кнопки: `stop up edge mode f1 right acdc auto 50 menu trigup left trigdn
save trig down f2 shift`.

`shot` ждёт конца прохода развёртки (трасса рисуется по столбцу за проход
главного цикла, произвольный момент — это смесь двух кадров). Панели FFT и
декодера на живом захвате перерисовываются каждый проход — в сценариях перед
ними нажимается `stop`.

## Диагностика

```sh
--heartbeat 1000 --watchdog 2000
```

```text
[emu] hb:  2281.7 ms emulated | 20.71 s host (0.11x) | 27.5 MIPS | 309 frames, avg 7.4 ms, worst 287.1 ms
```

Watchdog срабатывает, когда на дисплей ничего не приходит дольше порога
(прогресс меряется по записям в панель), и печатает состояние ядра и захвата:

```text
[emu] WATCHDOG: nothing drawn for 2000 ms of emulated time
[emu]   core:  pc 0x0800a1c4  sp 0x1000fd20  lr 0x08009f31  in handler  irq MASKED
[emu]   board: dma run buf1 cnt 8192/8192 COMPLETION UNSERVICED  irq en/PENDING  sampling  relay 3 dac 2010
```

Exit code 2, если зависание было, — сценарий в CI упадёт, а не запишет
замёрзший кадр.

## Ограничения

- DOOM-сборка (`make DOOM=1`) работает, но рендерер под эмуляцией заметно
  медленнее прибора.
- SWD, USB, RTC не моделируются — прошивка их не использует.
