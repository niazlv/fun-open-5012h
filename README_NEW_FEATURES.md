# Новые функции отладки и анализа

Добавлены две новые функции для отладки и анализа системы:

## 1. CoreDump Viewer (Просмотрщик дампов памяти)

### Описание
Система автоматического захвата и анализа ошибок с возможностью просмотра через удобный интерфейс.

### Возможности
- **Автоматический захват ошибок**: При любой ошибке (Hard Fault, Timer Overflow, общие ошибки)
- **Стек трейс**: Анализ последовательности вызовов функций
- **Регистры процессора**: Состояние всех регистров на момент ошибки
- **Системная информация**: Память, таймеры, состояние системы
- **Интерактивный просмотр**: Удобная навигация по дампам

### Как использовать
1. **Доступ через меню**: Выберите "CoreDump Viewer" в главном меню
2. **Автоматический захват**: Система автоматически сохраняет дампы при ошибках
3. **Навигация**:
   - **UP/DOWN**: Выбор дампа в списке
   - **RIGHT**: Переход к детальному просмотру
   - **LEFT**: Возврат к списку
   - **UP/DOWN** (в детальном режиме): Переключение страниц (детали/регистры/стек)
   - **F1**: Выход

### Типы ошибок
- Timer Overflow (переполнение таймера)
- Hard Fault (критические ошибки процессора)
- General Error (общие ошибки приложения)
- Assertion Failed (ошибки утверждений)
- Memory Error (ошибки доступа к памяти)

### Информация в дампе
- **Детали ошибки**: Тип, сообщение, время, PC/LR/SP
- **Регистры**: R0-R3, R12, PSR, CFSR, HFSR, MMAR, BFAR
- **Стек трейс**: До 16 уровней вызовов функций
- **Системное состояние**: Свободная память, активные таймеры

## 2. Flash Viewer (Просмотрщик flash памяти)

### Описание
Интерактивный просмотрщик содержимого flash памяти с автоматическим анализом структуры.

### Возможности
- **Hex просмотр**: Шестнадцатеричное представление с ASCII
- **ASCII режим**: Текстовое представление данных
- **Анализ структуры**: Автоматическое определение секций памяти
- **Простая дизассемблировка**: Базовый анализ ARM Thumb инструкций
- **Навигация**: Быстрое перемещение по памяти

### Как использовать
1. **Доступ через меню**: Выберите "Flash Viewer" в главном меню
2. **Режимы просмотра**:
   - **F1**: Переключение режимов (Hex/ASCII/Structure/Disasm)
   - **F2**: Быстрый переход к структуре памяти
3. **Навигация**:
   - **UP/DOWN**: Прокрутка по строкам
   - **LEFT/RIGHT**: Прокрутка по страницам
   - **MENU**: Выход в главное меню

### Режимы просмотра

#### Hex Mode
- Адрес + 16 байт в hex + ASCII представление
- Классический hex dump формат
- Удобно для анализа бинарных данных

#### ASCII Mode
- Фокус на текстовом содержимом
- Отображение строк и текстовых данных
- Полезно для поиска строковых констант

#### Structure Mode
- Автоматический анализ секций памяти:
  - **Vector Table**: Таблица векторов прерываний
  - **Text Section**: Код программы
  - **Data Section**: Инициализированные данные
  - **BSS Section**: Неинициализированные данные
  - **String Data**: Найденные строковые данные
- Навигация по секциям с **UP/DOWN**
- **RIGHT**: Переход к просмотру выбранной секции

#### Disasm Mode
- Простая дизассемблировка ARM Thumb инструкций
- Базовый анализ типов инструкций
- Полезно для анализа кода

### Автоматический анализ
Система автоматически:
- Определяет границы секций из linker script
- Ищет строковые данные в памяти
- Анализирует структуру программы
- Предоставляет навигацию по найденным секциям

## Интеграция в систему

### Меню
Обе функции доступны через главное меню системы:
- Выберите нужное приложение из списка
- Используйте кнопки навигации для управления
- **MENU** для возврата в главное меню

### Автоматическая работа CoreDump
- При любой ошибке система автоматически сохраняет дамп
- На экране появляется сообщение "CoreDump saved!"
- После перезагрузки можно просмотреть дампы через меню
- Дампы сохраняются в RAM (теряются при выключении)

### Производительность
- Минимальное влияние на производительность системы
- Захват дампов происходит только при ошибках
- Flash viewer работает в реальном времени
- Оптимизированная отрисовка интерфейса

## Отладка с новыми инструментами

### Анализ ошибок
1. При возникновении ошибки система сохранит дамп
2. Перезагрузите устройство
3. Откройте CoreDump Viewer через меню
4. Анализируйте:
   - PC адрес для определения места ошибки
   - Стек трейс для понимания последовательности вызовов
   - Регистры состояния для типа ошибки
   - Системное состояние на момент ошибки

### Анализ памяти
1. Откройте Flash Viewer через меню
2. Используйте Structure режим для обзора
3. Переходите к интересующим секциям
4. Анализируйте содержимое в Hex или ASCII режиме
5. Используйте Disasm для анализа кода

### Советы по использованию
- Регулярно проверяйте CoreDump Viewer на наличие новых дампов
- Используйте Flash Viewer для понимания структуры прошивки
- Анализируйте стек трейс для поиска источника ошибок
- Сохраняйте важную информацию из дампов до выключения устройства

Эти инструменты значительно упрощают процесс отладки встраиваемых систем и помогают быстро находить и исправлять ошибки.

# Функции осциллографа (2026-07)

## Расширенные измерения (кнопка MODE)

Измерения считаются по всей записи захвата (модуль `measure.c`, проверен
host-тестами на синтетических сигналах — `tests/host_test.c`):

- **Страница M**: Vpp и частота
- **Страница R** (сменяется каждые 2 с): Vrms (истинное СКЗ) и duty cycle

Частота определяется по пересечениям средней линии сигнала с адаптивным
гистерезисом (10% от размаха) и субсэмпловой интерполяцией — работает
независимо от положения уровня триггера и устойчива к шуму.

## FFT-спектроанализатор (SHIFT+MODE)

Спектр 512-точечного FFT (окно Ханна, аппаратный FPU) вместо осциллограммы:
динамический диапазон 60 дБ, нормировка на максимум. Повторное SHIFT+MODE
возвращает осциллограмму.

**Анализируется вся запись, а не последние 512 отсчётов.** Это ключевой
момент: разрешение по частоте равно 1/(время записи), а не половине частоты
дискретизации. 512 точек берутся из записи с прореживанием `decim`
(окно 3·decim отсчётов, веса 1:2:1 — трёхкратный box-фильтр), так что
преобразование покрывает всю запись целиком и не даёт внеполосному шуму
завернуться в отображаемую полосу. На развёртке 5 мс/дел запись = 100 мс →
шаг сетки 10 Гц, и 50 Гц отделяются от 100 Гц; на 50 мс/дел — ~1 Гц.
Раньше преобразовывались 512 сырых отсчётов той же записи (0.5 мс, шаг
2 кГц): сеть 50 Гц + гармоники + наводки давали одно бессмысленное число
вроде «194 Гц».

Панель разбора (правый верхний угол):

- `F0` — основная частота и THD. Определяется не по самому высокому пику, а
  по **гармонической гребёнке**: перебираются все пики и их субгармоники,
  выигрывает та гребёнка, которая объясняет больше всего энергии спектра
  (при равенстве — более высокая частота, иначе всегда «выигрывала» бы F0/2).
  Если самый сильный пик — третья гармоника 150 Гц, F0 всё равно 50 Гц;
  работает и при полностью отсутствующей основной (300+450+600 → 150 Гц).
- `df` / `BW` — шаг сетки и верх спектра. `*` рядом с BW = полоса выбрана
  вручную.
- До 5 сильнейших пиков: `h<n>` — номер гармоники F0 (белым), `-` —
  негармонический пик (оранжевым: наводка, второй источник, шум),
  частота и уровень в дБ относительно сильнейшего.
- Нижняя строка — уровень шумового пола или показания курсора.

Управление в режиме спектра:

Режим спектра **модальный**: кнопки осциллограммы (уровень триггера,
панорама, автонастройка) сквозь него не проваливаются — весь ввод
перехватывает своя раскладка, наружу выходят только STOP (run/stop),
AC/DC (связь по входу) и SHIFT+MODE (выход).

- `←` / `→` — курсор по спектру (первое нажатие — на сильнейший пик)
- `▲` / `▼` — прыжок курсора по найденным пикам (по частоте, с закольцовкой)
- `←`+`→` — убрать курсор
- `TRIG▲` — шире полоса (шаг ×2), `TRIG▼` — мельче шаг `df` (шаг ÷2)
- `MODE` — показать/убрать панель разбора (спектр на весь экран)
- `50%` — курсор на сильнейший пик
- `SHIFT`+`←`/`→` — развёртка (она же задаёт длину записи → разрешение)
- `SHIFT`+`▲`/`▼` — вертикальная шкала (диапазон АЦП)

Отрисовка — классический вид анализатора: непрерывная кривая (сшивается из
точек так же, как осциллограмма), под ней заливка тепловым градиентом по
уровню — тихие участки светятся сине-зелёным, сильный пик прорастает через
жёлтый в красное ядро. Цвет сам по себе показывает уровень. Над найденными
пиками плавают маркеры-штрихи: **белый** = гармоника F0, **оранжевый** =
посторонний пик (наводка, второй источник). Курсор — штрих-линия, опущенная
сверху на кривую; его частота и уровень дублируются в статус-строке, без
курсора там F0 и df.

Полоса по умолчанию выбирается автоматически: самая узкая (т.е. с лучшим
разрешением), при которой измеренная частота остаётся минимум в 6 раз ниже
верха спектра. Сеть попадает на полный разбор записи, 10 МГц меандр — на
сырую частоту дискретизации.

### Анализ после СТОП

Спектр пересчитывается по замороженной записи при переходе RUN→STOP и
обратно, и при любом действии пользователя (курсор, полоса, развёртка,
вертикаль). Остановленный прибор отдаёт **сырую** запись 96 K вместо
прореженной 24 K — то же время записи, но вчетверо больше полосы в запасе
(лишние два шага `TRIG▲`). Пока прибор работает, спектр обновляется не чаще
10 Гц, чтобы не занимать шину LCD.

Побочно исправлено: `capture_stop()` теперь разворачивает чересстрочный
двухканальный буфер (`buffer_reverse`), как это делал только автостоп
одиночного запуска. Без этого на самой быстрой развёртке (50 нс/дел, два
АЦП вперемежку, нечётные байты в обратном порядке бит) остановленная запись
была мусором на каждом втором отсчёте — не только для FFT, но и для
осциллограммы и декодеров.

## Автонастройка (кнопка AUTO)

Итеративно (до 5 с): выводит сигнал из клиппинга / растягивает мелкий сигнал
по вертикали, центрирует, ставит триггер на 50% размаха и подбирает развёртку
на ~2.5 периода. Работает по свежим кадрам захвата, не блокируя интерфейс.

## Триггер на 50% (кнопка 50P)

Мгновенно ставит уровень триггера на середину между измеренными минимумом и
максимумом сигнала.

## Замечания

- Захват полностью аппаратный (TIMER7 → DMA): новые функции не влияют на
  частоту дискретизации, обработка идёт по уже захваченным кадрам.
- Host-тесты: `cc -O2 -I. tests/host_test.c measure.c fft.c -lm -o /tmp/t && /tmp/t`

## Определение типа сигнала (страница S измерений)

Третья страница измерений (MODE, страницы сменяются каждые 2 с): тип сигнала —
Sine / Square / Pulse / Triangle / Sawtooth / DC / Noise — плюс THD
(коэффициент гармоник по 2–5 гармоникам FFT). Классификатор (`classify.c`)
использует отношение СКЗ к амплитуде, duty cycle, баланс наклонов
(пила vs треугольник) и регулярность периодов (отсев шума).

## UART-автодекодер (SHIFT+EDGE)

Одноканальный логический анализатор для UART: автоопределение полярности и
скорости (снап к стандартным 4800…2M при отклонении <4%), декодирование 8N1.
Панель поверх осциллограммы: скорость, счётчик ошибок кадров, последние
16 байт в hex и ASCII. При входе триггер автоматически ставится на 50%.
Рабочие таблицы декодера живут в свободных 8 КБ SRAM после буферов захвата
(`CAPTURE_SPARE_RAM`), TCM не тратится. I2C/SPI недоступны принципиально —
у прибора один канал.

Все алгоритмы (`measure.c`, `fft.c`, `classify.c`, декодеры) — чистый C,
покрыты host-тестами (91 проверка):

```sh
cc -O2 -I. tests/host_test.c measure.c fft.c classify.c uart_decode.c \
   logic_decode.c nec_decode.c onewire_decode.c ws2812_decode.c -lm -o /tmp/t && /tmp/t
```
