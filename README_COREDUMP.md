# Debug CoreDump System

Система отладки CoreDump для встраиваемых систем, которая позволяет захватывать и анализировать информацию об ошибках и сбоях системы.

## Возможности

- **Автоматический захват ошибок**: Система автоматически сохраняет информацию при возникновении ошибок
- **Стек трейс**: Захват стека вызовов для анализа последовательности функций
- **Регистры процессора**: Сохранение состояния всех регистров на момент ошибки
- **Системная информация**: Информация о состоянии памяти, таймеров и других компонентов
- **Интерактивный просмотр**: Удобный интерфейс для просмотра сохраненных дампов

## Типы ошибок

Система поддерживает следующие типы ошибок:

- `ERROR_TYPE_TIMER_OVERFLOW` - Переполнение таймера
- `ERROR_TYPE_HARD_FAULT` - Критическая ошибка процессора
- `ERROR_TYPE_GENERAL_ERROR` - Общие ошибки приложения
- `ERROR_TYPE_ASSERTION_FAILED` - Ошибки утверждений
- `ERROR_TYPE_MEMORY_ERROR` - Ошибки доступа к памяти

## Использование

### Инициализация

```c
#include "debug_coredump.h"

// В функции main()
debug_coredump_init();
```

### Захват ошибок

#### Автоматический захват
Система автоматически захватывает:
- Hard Fault исключения
- Timer overflow ошибки
- Общие ошибки через функцию `error()`

#### Ручной захват
```c
// Простой способ с автоматическим получением PC/LR/SP
COREDUMP_CAPTURE(ERROR_TYPE_MEMORY_ERROR, "Memory access violation");

// Или с явным указанием параметров
debug_coredump_capture(ERROR_TYPE_GENERAL_ERROR, "Custom error", pc, lr, sp);
```

### Просмотр дампов

#### Через кнопку F1
- Нажмите **F1** для открытия просмотрщика дампов (если есть сохраненные дампы)
- Используйте кнопки навигации для просмотра:
  - **UP/DOWN**: Выбор дампа в списке
  - **RIGHT**: Переход к детальному просмотру
  - **LEFT**: Возврат к списку
  - **UP/DOWN** (в детальном режиме): Переключение между страницами (детали/регистры/стек)
  - **F1**: Выход из просмотрщика

#### Программно
```c
// Показать просмотрщик дампов
debug_coredump_show_viewer();

// Проверить количество дампов
int count = debug_coredump_get_count();

// Очистить все дампы
debug_coredump_clear_all();
```

## Интерфейс просмотрщика

### Список дампов
Показывает все сохраненные дампы с информацией:
- Номер дампа
- Тип ошибки
- Program Counter (PC)
- Время возникновения

### Детальный просмотр
Содержит три страницы:

#### 1. Детали ошибки
- Тип и сообщение ошибки
- Время возникновения
- Значения PC, LR, SP
- Информация о свободной памяти

#### 2. Регистры процессора
- Регистры R0-R3, R12, PSR
- Регистры состояния ошибок (CFSR, HFSR, MMAR, BFAR)

#### 3. Стек трейс
- Последовательность вызовов функций
- Адреса Program Counter для каждого уровня
- Значения Stack Pointer

## Интеграция в проект

### 1. Добавьте файлы в проект
- `debug_coredump.h`
- `debug_coredump.c`

### 2. Обновите main.c
```c
#include "debug_coredump.h"

// В main()
debug_coredump_init();

// В основном цикле
debug_coredump_viewer_task();

// В обработчике кнопок
if (debug_coredump_viewer_is_active()) {
    debug_coredump_viewer_buttons_handler(buttons);
    return;
}

if (buttons & BTN_F1) {
    if (debug_coredump_get_count() > 0) {
        debug_coredump_show_viewer();
        return;
    }
}
```

### 3. Обновите обработчик Hard Fault
```c
void irq_handler_hard_fault_c(uint32_t lr, uint32_t msp, uint32_t psp)
{
    // Захватить coredump
    debug_coredump_capture_hard_fault(lr, msp, psp);
    
    // Остальная обработка...
}
```

### 4. Обновите функцию error()
```c
void error(char *text)
{
    // Захватить coredump
    COREDUMP_CAPTURE(ERROR_TYPE_GENERAL_ERROR, text);
    
    // Остальная обработка...
}
```

## Тестирование

Используйте файлы `test_coredump.c` и `test_coredump.h` для тестирования системы:

```c
#include "test_coredump.h"

// Показать тестовое меню
test_coredump_menu();

// Обработать кнопки в тестовом режиме
test_coredump_buttons_handler(buttons);
```

Тестовое меню позволяет:
- Генерировать различные типы ошибок
- Тестировать захват дампов
- Проверять работу просмотрщика

## Конфигурация

В `debug_coredump.h` можно настроить:

```c
#define MAX_STACK_TRACE_DEPTH   16    // Глубина стека трейса
#define MAX_ERROR_MESSAGE_LEN   64    // Длина сообщения об ошибке
#define MAX_COREDUMP_ENTRIES    8     // Максимальное количество дампов
```

## Ограничения

- Дампы сохраняются только в RAM и теряются при перезагрузке
- Стек трейс может быть неточным из-за оптимизации компилятора
- Требует достаточно RAM для хранения дампов
- Простая реализация unwinding стека (может потребовать улучшения)

## Расширение функциональности

Система может быть расширена:

1. **Сохранение в Flash**: Для сохранения дампов между перезагрузками
2. **Улучшенный stack unwinding**: Более точный анализ стека
3. **Символьная информация**: Отображение имен функций
4. **Экспорт дампов**: Передача дампов на внешние устройства
5. **Фильтрация**: Настройка типов ошибок для захвата

## Отладка

При возникновении ошибки:

1. Система автоматически сохранит дамп
2. На экране появится сообщение "CoreDump saved!"
3. После перезагрузки нажмите **F1** для просмотра
4. Анализируйте PC адрес для определения места ошибки
5. Используйте стек трейс для понимания последовательности вызовов
6. Проверьте регистры состояния для определения типа ошибки

Эта система значительно упрощает отладку встраиваемых систем, предоставляя детальную информацию о сбоях и ошибках.
